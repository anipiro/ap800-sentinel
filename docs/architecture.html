What is missing

  • No service manual, alarm list or wiring diagram. The offer is a sales document.
  • The controller brand behind the Weintek panel is not stated.
  • No recording of the machine failing. The long video is silent, so there is less than a minute of real machine sound.

What that means

Nothing here can train a fault detector. The device has to record the healthy machine on site first, learn what normal looks like for each recipe, and flag departures from it. Fixed limits taken from the rated figures cover the first weeks.

The device

A kit of sensors that attach without changing the machine, wired to one sealed box mounted beside it. Dumpling lines are washed down, so everything near the product is rated IP67 or better and nothing sits above open dough or filling.

System architecture

How a fault is decided

  1. Fixed limits from the rated figures and the recipe. Live from day one.
  2. Learned bands per recipe, from two to four weeks of normal running.
  3. Models that combine signals: an anomaly score for the drives, a defect classifier for the camera.
  4. One incident per cause, with the evidence, the likely reason and what to check. Operators mark each one real or false, and that feedback retrains the bands.

Technology

  • Edge box: Python services in Docker, OpenCV and ONNX for vision, a local MQTT broker, a disk buffer.
  • Server: Next.js and TypeScript for the site and its API, Postgres with TimescaleDB, object storage for clips.
  • Live updates to the browser by server-sent events.
  • Hosting: cloud by default. The same stack runs on one on-site server if the plant does not allow outside connections.

Data schema

The chain is machine, component, sensor, reading. A run ties readings and camera results to the recipe in use. Rules and baselines produce incidents, and incidents produce notifications. Fields in blue link to another table.

machine

One row per AP800

  • id
  • name, model, serial
  • site, timezone
  • commissioned_at

component

A station or drive on the machine

  • id
  • machine_id
  • name
  • kind: hopper, roller_stage, drum, pump, conveyor, drive
  • position in line

sensor

One measurement channel

  • id
  • component_id
  • kind, unit
  • sample_rate_hz
  • status, last_seen_at

recipe

What the machine is set up to make

  • id
  • machine_id
  • form_code, e.g. V18Ts2
  • product_weight_g
  • dough_thickness_mm
  • filling_pct, target_kg_h

run

One stretch of production

  • id
  • machine_id, recipe_id
  • started_at, ended_at
  • operator
  • kg_produced

reading

Time-series, one row per second per feature

  • time, sensor_id, feature
  • run_id
  • value
  • feature: rms, peak, band_1 … band_n, mean

inspection

Camera result per second

  • time, sensor_id
  • run_id
  • product_count, ok_count
  • defects: open_seam, leak, joined, missing, misshapen
  • mean_area_mm2
  • snapshot_url

baseline

What normal looks like

  • id
  • sensor_id, recipe_id
  • feature
  • mean, std, low, high
  • trained_from, trained_to

rule

A fixed or learned check

  • id
  • component_id
  • name, condition
  • severity: info, warning, critical
  • hold_seconds, enabled

incident

One detected problem

  • id
  • machine_id, component_id, run_id, rule_id
  • severity, status
  • opened_at, closed_at
  • probable_cause, evidence
  • acknowledged_by
  • verdict: real, false_alarm

notification

A message sent about an incident

  • id
  • incident_id, user_id
  • channel
  • sent_at, delivered

maintenance_task

Scheduled service work

  • id
  • component_id
  • title, interval_hours
  • last_done_at, due_at
  • done_by

user

Who sees what and who is called

  • id
  • name
  • role: operator, technician, manager, admin
  • phone, telegram_id

Build order

  1. Site survey

    Identify the controller and panel model, photograph the cabinet, choose mounting points, and confirm the fault list with the operators. About a week.

  2. Website on a simulated machine

    Build the full site and data pipeline against a simulator that produces realistic AP800 signals and injects each fault from the table. This gives a working product to review before any hardware is bought.

  3. Core kit on the real machine

    Install current sensors, three vibration sensors, camera A and the edge box. Fixed limits go live. Record normal running for each recipe.

  4. Learned detection

    Switch on learned bands and the camera defect model. Add the controller link, camera B, pressure and thickness sensors.

  5. Prediction and reports

    Wear trends, service forecasts, shift and weekly reports, further machines.

Decisions needed before building

  1. Is the machine installed and running, and can we get to it and its electrical cabinet? The files are a quotation, so this is not clear.
  2. Start with the simulated machine, or go straight to hardware? Recommended: simulator first.
  3. Which matters most: bad products, stoppages, or breakdowns? This sets which sensors come first.
  4. May data leave the factory, or must the server sit on site?
  5. Will Signal-Pack share the controller's data points? Without them the link to the panel takes longer, and the rest still works.
  6. Hardware budget, and whether industrial-grade parts are required or a cheaper prototype is acceptable for the first trial.
